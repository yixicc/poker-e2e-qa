# WePoker 画面与拆手细则

默认竖屏 `512×1088`。坐标是相对整帧的比例。

## 裁切

| 目标 | 裁切 `(x0,y0,x1,y1)` |
|---|---|
| Hero 底牌带 | `0.20, 0.74, 0.80, 0.98`，再在带内 `y 0.30–0.88` 找两张 |
| 公牌带 | `0.15, 0.36, 0.85, 0.50` |
| 桌心水印（桌号/倒计时） | 约 `y 0.40–0.52` |
| Hero 筹码 | 底栏头像下，「高牌/对子」下方，Vision 坐标 `y` 靠近 0（底边） |

牌面检测：`lum>90` 且不是绿绒 `(g>r+15)&(g>b+8)`。两张底牌取中心附近、宽约 52px、间隙约 6px 的一对。公牌取连续 3/4/5 个同样宽度的条。

牌面再收一层白/灰纸（去掉桌布和头像肤色）。红背 `POKER`：浅色占比低且偏红，整帧丢掉。

## 花色 / 点数

四色：S 黑、H 红、D 蓝、C 绿。

花色用**牌心油墨**投票；贴边的绿绒不算梅花。红心 JPEG 发灰，不要用「够不够白」。

点数 OCR 顺序：`_r`（放大角标）→ `_rb`（二值）→ `_c`（整张）。Q 常常只有 `_rb` 或整张读得出。心形会被 OCR 成 `9`，所以有 `_r/_rb` 时不要用整张上的 `9`。

模糊等价（拆手时当同一张，不要新开一手）：

- 点数 `6` ↔ `9` 且花色相同
- 花色 `C` ↔ `S` 且点数相同

## 拆手 / 合并

同一手：后一帧公牌是前一帧的前缀（允许上面两条模糊等价），例如 `QD 6D KH` → 后面河牌仍以这三张开头。

两局：公牌清零后再发出对不上前缀的新翻牌，**并且**底牌也换了。例：`JD 7C` + `QD 6D KH` 之后变成 `QH KS` + `7S 4H 5H 6D 3C`。

假两局（必须合并）：

- 分段 `_b.jpg` 被排到时间轴开头（它其实是片尾）
- 中间一帧微信遮住，前后公牌相同或变长
- 只抖了一张的 C/S 或 6/9

合并时：公牌取更长的那串；底牌保留先读到的稳定值。

## 筹码口径

- 入座带入：坐下后第一手的起始栈。不要把「入座 2000 + 立刻补码 2000」写成开局 4000。
- 中途补码：爆 0 后再买入，单独记账。
- 盈亏：`离桌 − 入座 − 补码`。
- 切桌：用水印六位桌号 + 倒计时跳变，不用桌名。一场里可以 桌1→桌2。

## OCR

```bash
swift scripts/ocr_vision.swift list.txt
# stdout: JSON [{path,text,x,y,w,h,conf}, ...]
```

Vision 的 `y=0` 在**图片底边**。批量 OCR，不要对每一帧单独起 swift。

## Excel

手数对账一行一手。列顺序固定：

1. 房间（桌1/桌2）
2. 桌号（六位）
3. 段号（有 traces 用 segmentNo；整场片用手序号）
4. 分段（UUID 或 `mm:ss–mm:ss`）
5. 手牌（`4S 7D`）
6. 公牌（空 / 3 / 4 / 5 张）
7. hero初始筹码
8. hero结束筹码
9. 切局是否正常
10. 是否识别到
11. 异常原因

同切片两局：两行同分段，黄底，「切局是否正常」= 否。

不算手的行可以留着对账（等待/补码），手牌公牌空，异常原因写清楚。
