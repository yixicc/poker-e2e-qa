    这张表怎么读

    要看「谁写得好」，先看生成行的证据绑定、伤害性错误、主泄漏，再看综合分。调用成功和终态成功不能说明教球质量。

    deepseek 绑定 61%、主泄漏只对 42%，所以按新通过线首轮通过会从 26% 掉到大约 18%。豆包伤害错误更高。评审行只显示它判过的比例。

    还缺的账本字段

    1. stage / round / fallback
    2. prompt + completion token
    3. 评审分 0–5、否决原因、绑定率 / 伤害 / 主泄漏
    4. experiment_id（重跑是否污染对照）
    谁打分，怎么算过

    规则试行，以后只改权重和门槛，不改「生成不打分、评审不改写」这条分工。

    生成模型

    只根据输入事实写报告。调用成功只代表稿子写出来了，不等于报告通过。

    当前：deepseek-v4-flash。不给自己打分，也不能当评审。

    评审模型

    只读「输入事实 + 生成稿」，打四维分，并判断主泄漏和牌理。不改正文。绑定率和伤害性错误由程序先算。

    当前：gemini-3.7-flash。必须和生成模型不同。

    数据准备 / 兜底

    准备失败（范围对不上、事实未就绪）直接失败，不进质量分。兜底是换模重写，测试期关闭。

    准备是系统规则，不是模型能力。

    基础综合分仍用四维：事实×40% + 逻辑×30% + 结构×15% + 范围×15%。输出能不能过，还要过下面三条硬指标。

    通过：无伤害性错误，证据绑定 ≥ 80%，主泄漏抓对，事实 ≥ 4，综合分 ≥ 4.0 不通过：硬指标或分数未达标，回原生成模型修订 一票否决：伤害性错误，或主泄漏明显抓错，或事实 ≤ 2 / 范围 ≤ 2
    维度谁算看什么卡线
    事实一致 / 逻辑 / 结构 / 范围评审模型 原先四维，用于综合分 事实 ≥ 4 且综合 ≥ 4.0；事实或范围 ≤ 2 否决
    证据绑定率程序 亮点、改进是否挂了本场真实存在的 handId ≥ 80% 才能过。没挂手的建议当套话
    伤害性错误程序 + 评审 盈亏写反、位置反了、摊牌牌搞错、引用了不存在的手 出现即否决，权重大于文笔
    主泄漏是否抓对评审模型 rank 1 的改进是不是本场最大的钱/结构性错误，而不是最戏剧的一手 抓错主泄漏，即使事实全对也不过
    建议可执行性程序粗判 + 评审 改进里有没有「下次遇到 X 就做 Y」的硬规则 先记分，暂不单独否决
    修订是否变好程序 同一份稿后一轮的绑定率、综合分是否高于前一轮 只观察，用于判断修订有没有用
    牌理是否站得住评审模型 建议和输入统计、公开德州常识不打架 事实对但牌理错，记入不通过原因

    引用可核验率（文中 VPIP、人数、牌面能否对上输入）并进证据绑定一起算，不单开一列，避免评价台过碎。
